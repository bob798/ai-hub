# 维护指南

本项目是**零依赖纯静态单页应用**,没有构建步骤。所有「内容」（课程、测验、闪卡、面试题、术语）都集中在一个文件 `js/data.js`，改内容 = 改这个文件里的数组。改完直接刷新浏览器即可看到效果。

> 想先跑起来：在项目根目录执行 `python3 -m http.server 8000`，浏览器打开 `http://localhost:8000`。

---

## 目录与职责

| 文件 | 职责 | 改它的场景 |
|---|---|---|
| `index.html` | 入口、顶部导航 | 增减导航菜单项 |
| `css/style.css` | 全部样式（暗色主题、响应式） | 调外观 |
| `js/data.js` | **全部内容数据** | 增改课程/测验/闪卡/面试题/术语（最常改） |
| `js/app.js` | 路由 + 状态(localStorage) + 各页面渲染 | 改功能逻辑、加新页面 |
| `js/tutor.js` | AI 导师：Claude API 流式调用 + Markdown 渲染 | 改导师行为、模型、提示词 |
| `.github/workflows/deploy-pages.yml` | GitHub Pages 自动部署 | 改部署流程 |

**数据与逻辑分离**：日常维护内容只动 `js/data.js`，不需要碰渲染逻辑。

## 如何增改内容（最常见任务）

所有数据结构都在 `js/data.js`。下面给出每种内容的字段说明与示例，照着复制改即可。

### 1. 新增 / 修改课程

课程挂在 `CURRICULUM` 数组下，结构是「阶段 → 课程」两层。

```js
{
  id: "s1",                    // 阶段唯一 id（s1~s6）
  title: "阶段一 · 基础准备",
  subtitle: "Python 与数学基础",
  weeks: "建议 3–5 周",
  desc: "阶段简介……",
  lessons: [
    {
      id: "s1l1",              // 课程唯一 id，约定 <阶段id>l<序号>
      title: "Python 快速上手",
      minutes: 90,             // 预估时长（分钟），显示用
      content: `<p>正文 HTML……</p>`,   // 见下方“正文写法”
      resources: [             // 推荐资源链接
        { name: "资源名", url: "https://…" }
      ]
    }
  ]
}
```

**正文写法**：`content` 是一段 HTML 字符串（用反引号包裹）。常用标签：
- `<p>段落</p>`、`<h3>小标题</h3>`
- `<ul><li>无序项</li></ul>`、`<ol><li>有序项</li></ol>`
- `<strong>重点</strong>`（会显示成黄色）、`<code>行内代码</code>`
- `<a href="…" target="_blank" rel="noopener">链接</a>`

> ⚠️ 这里的 HTML 是开发者自己写、可信的，所以直接渲染。**不要**把用户输入塞进 `content`。

**新增一个阶段**别忘了三件事：① 在 `CURRICULUM` 加阶段对象；② 在 `QUIZZES` 加同名 `id` 的测验数组（否则「阶段测验」按钮会跳回路径页）；③ 阶段 `id` 与课程 `id` 全局唯一。

### 2. 新增 / 修改测验题

`QUIZZES` 是一个对象，键 = 阶段 id，值 = 该阶段的题目数组。

```js
QUIZZES = {
  s1: [
    {
      q: "题干？",
      options: ["选项A", "选项B", "选项C", "选项D"],
      answer: 1,                // 正确答案在 options 里的下标，从 0 开始（这里指 B）
      explain: "答案解析，会在作答后展示。"
    }
  ]
}
```

- `answer` 必须是合法下标（`0 ≤ answer < options.length`），写错会被校验脚本拦下。
- 每题都要写 `explain`，这是学习闭环的关键。

### 3. 新增 / 修改闪卡

`FLASHCARDS` 数组，每张卡正面是概念、背面是解释。复习计划由 Leitner 间隔重复算法自动管理（盒子 0→1→3→7→16 天）。

```js
{
  id: "f31",          // 全局唯一 id
  tag: "LLM",         // 分类标签：ML / DL / LLM / Agent / 工程
  front: "概念名",
  back: "解释（一两句话讲清）。"
}
```

新增标签会自动出现，无需改别处。

### 4. 新增 / 修改面试题

`INTERVIEW_QA` 数组，按 `cat` 分类自动分组展示。

```js
{ cat: "机器学习", q: "问题？", a: "参考答案。" }
```

### 5. 新增 / 修改术语

`GLOSSARY` 数组，支持中英文搜索。

```js
{ term: "中文术语", en: "English Term (缩写)", def: "一句话定义。" }
```

## 改完后的自检

提交前务必跑两步校验（需本机有 Node.js）。

**① 语法检查**

```bash
node --check js/data.js && node --check js/app.js && node --check js/tutor.js
```

**② 数据完整性校验**（检查 id 唯一、阶段都有测验、测验答案下标合法、闪卡 id 不重复）

```bash
node -e '
const fs=require("fs"),vm=require("vm");
const code=fs.readFileSync("js/data.js","utf8")+";({CURRICULUM,QUIZZES,FLASHCARDS,INTERVIEW_QA,GLOSSARY})";
const {CURRICULUM,QUIZZES,FLASHCARDS}=vm.runInNewContext(code);
let errs=[],ids=new Set();
for(const s of CURRICULUM){
  if(!QUIZZES[s.id]) errs.push("阶段缺测验:"+s.id);
  for(const l of s.lessons){
    if(ids.has(l.id)) errs.push("重复课程id:"+l.id); ids.add(l.id);
    if(!l.content||!l.resources.length) errs.push("内容/资源缺失:"+l.id);
  }
}
for(const [k,qs] of Object.entries(QUIZZES)) for(const q of qs){
  if(q.answer<0||q.answer>=q.options.length) errs.push("答案越界:"+k);
  if(!q.explain) errs.push("缺解析:"+k);
}
const f=new Set();
for(const c of FLASHCARDS){ if(f.has(c.id))errs.push("重复闪卡id:"+c.id); f.add(c.id); }
if(errs.length){console.error("❌",errs);process.exit(1);}
console.log("✅ 校验通过");
'
```

最后在浏览器里点一遍改动的页面确认显示正常。

## 关于 AI 导师（`js/tutor.js`）

- **模型**：常量 `TUTOR_MODEL`（默认 `claude-opus-4-8`）。换模型只改这一处。
- **教学风格**：常量 `TUTOR_SYSTEM`（system prompt）。想调整导师语气/范围改这里。
- **API Key**：由用户在「AI 导师」页填写，存浏览器 `localStorage`，请求由浏览器**直连** Anthropic（带 `anthropic-dangerous-direct-browser-access: true` 头）。项目本身**不含也不需要**任何密钥，不要把密钥写进代码或提交。
- **Markdown 渲染**：`mdToHtml()` 是自带的轻量解析器，先转义后格式化（防 XSS，忽略 `javascript:` 链接）。支持代码块、列表、行内代码、加粗、斜体、链接。

## 部署（GitHub Pages）

仓库已配置自动部署工作流 `.github/workflows/deploy-pages.yml`：**每次推送到 `main` 分支**会自动把根目录静态站点部署到 GitHub Pages。

### ⚠️ 首次需手动开启一次 Pages

GitHub 的安全限制：Actions 令牌无法「凭空创建」Pages 站点，必须仓库所有者先启用一次。操作：

1. 打开 `https://github.com/bob798/ai-hub` → **Settings** → **Pages**
2. **Build and deployment → Source** 选 **GitHub Actions**，保存
3. 之后回到 **Actions** 页，对失败的 “Deploy to GitHub Pages” 运行点 **Re-run jobs**（或随便往 main 推一次）

开启后**完全自动**：今后每次推送 main 都会自动重新部署，无需再手动干预。站点地址形如 `https://bob798.github.io/ai-hub/`。

> 备选方案：若不想用 Actions，也可在 Settings → Pages 把 Source 设为 “Deploy from a branch” → `main` / `root`，效果相同（同样需要先在 UI 里启用一次）。

## 数据安全 / 备份

- 所有学习进度（完成的课、测验成绩、闪卡复习计划、连续天数、对话）都存在浏览器 `localStorage`，键名见 `js/app.js` 的 `STORE_KEY`。
- 仪表盘底部提供**导出/导入备份**（JSON）。换设备或清缓存前先导出。
- 清空浏览器数据会丢失进度——这是纯前端应用的固有特性，靠备份功能兜底。

---

## 设计原则（改代码前请读）

1. **零依赖、零构建**：不要引入框架或打包工具，保持「下载即用、源码可读」。本项目本身也是一份教学素材。
2. **数据与逻辑分离**：内容进 `data.js`，逻辑进 `app.js`/`tutor.js`。
3. **渲染用户内容必先转义**：凡是来自用户/网络的文本，渲染前一律 `esc()` 或走 `mdToHtml()`，杜绝 XSS。
4. **优雅降级**：除 AI 导师外所有功能离线可用、不依赖任何后端。
